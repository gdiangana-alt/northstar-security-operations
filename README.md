# NorthStar Security Operations & Incident Response

Enterprise Azure security operations portfolio project demonstrating cloud telemetry collection, Microsoft Sentinel SIEM deployment, KQL detection engineering, scheduled analytics, incident investigation, and security response.

## Project Objective

The NorthStar Security Operations project demonstrates how Azure cloud activity can be transformed from raw telemetry into actionable security incidents.

The project implements and validates an end-to-end SOC workflow:

```text
Azure Control Plane
        ↓
Azure Activity Log
        ↓
Log Analytics
        ↓
Microsoft Sentinel
        ↓
KQL Detection
        ↓
Scheduled Analytics Rule
        ↓
Security Alert
        ↓
Sentinel Incident
        ↓
Investigation & Triage
        ↓
Classification
        ↓
Resolution
```

## Security Telemetry

Azure Activity Log telemetry is streamed at the subscription level to `NorthStar-SOC-Workspace`.

The telemetry provides visibility into Azure control-plane activity such as:

- Resource configuration changes
- Administrative operations
- Policy activity
- Diagnostic configuration
- Failed management operations

## Detection Engineering

A custom KQL detection was developed to identify failed Azure control-plane operations affecting the NorthStar environment.

```kusto
AzureActivity
| where ResourceGroup =~ "NORTHSTAR-AZURE-RG"
| where ActivityStatusValue =~ "Failure"
| project TimeGenerated, OperationNameValue, ActivityStatusValue, ResourceGroup
```

The detection was converted into a Microsoft Sentinel scheduled analytics rule.

### Analytics Rule

**Name:** `NorthStar - Failed Azure Control Plane Operation`

**Severity:** Medium  
**Frequency:** Every 5 minutes  
**Lookback:** 5 minutes  
**Threshold:** More than 0 matching events  
**Incident creation:** Enabled

## Detection Validation

A controlled Azure management failure was generated by attempting an invalid modification to the location of the existing NorthStar resource group.

Azure rejected the operation with `InvalidResourceGroupLocation`.

The resulting control-plane failure was:

1. Recorded by Azure Activity Log.
2. Ingested into Log Analytics.
3. Detected by the custom KQL query.
4. Matched by the scheduled Sentinel analytics rule.
5. Converted into a security alert.
6. Automatically associated with a Sentinel incident.

## Incident Response

The generated incident was investigated through Microsoft Sentinel in the Microsoft Defender portal.

The analyst reviewed the triggering operation, detection source, activity timestamps, alert context, and related event.

Investigation confirmed that the activity was authorized security testing rather than malicious activity.

**Final classification:** Benign Positive — Security Testing  
**Final status:** Resolved

No containment was required because Azure rejected the attempted change and no unauthorized modification occurred.

## MITRE ATT&CK Context

Failed Azure management operations are not inherently malicious.

The detection can provide supporting telemetry when investigating activity associated with scenarios such as:

- Account or permission manipulation
- Privilege-related administrative activity
- Attempts to alter defensive cloud configuration

ATT&CK mappings are treated as investigation context rather than evidence that a technique occurred.

See [`docs/mitre-attack-mapping.md`](docs/mitre-attack-mapping.md) for details.

## Troubleshooting & Engineering Challenges

The project included several real implementation and troubleshooting scenarios.

### Azure Policy vs. Sentinel

The existing NorthStar mandatory data-classification policy initially blocked deployment of a Sentinel-managed resource.

The issue demonstrated how broad governance controls can unintentionally interfere with platform security services.

### Activity Log Ingestion

Azure Activity telemetry initially did not appear in Sentinel.

The pipeline was validated independently at each stage, and a subscription-level diagnostic setting was configured to stream new Activity Log events to Log Analytics.

### Azure CLI Diagnostic Settings

An initial resource-level diagnostic-settings command failed because Azure Activity Log requires subscription-level configuration.

The implementation was corrected using the appropriate subscription diagnostic-settings command.

### Analytics Rule Validation

The Sentinel Rule Runs preview initially showed no execution records even though the scheduled detection subsequently generated an alert and incident.

The exercise demonstrated the importance of validating SIEM pipelines using actual telemetry and downstream detection outcomes rather than relying on a single portal status indicator.
